# HybridBSC

HybridBSC is a MATLAB/Python demo implementation for the paper **"A hybrid bit and semantic communication system"**. It demonstrates image-oriented hybrid bit and semantic communication over simulation channels and an ADALM-Pluto software-defined radio (SDR) link.

论文：Kaiwen Yu, Renhe Fan, Gang Wu, and Zhijin Qin, "A hybrid bit and semantic communication system," *Science China Information Sciences*, 69(1):119301, 2026. DOI: [10.1007/s11432-025-4622-x](https://doi.org/10.1007/s11432-025-4622-x).

## What This Demo Does

- Inserts semantic features into a bit-level image source through a watermark-like transform pipeline.
- Sends the hybrid image/data through a MATLAB WLAN Non-HT physical-layer workflow.
- Supports AWGN, Rayleigh, and Rician simulation channels.
- Supports over-the-air tests with ADALM-Pluto SDR hardware.
- Includes BPG/JPEG image compression experiments.
- Calls Python/PyTorch from MATLAB for MNIST semantic encoding, decoding, and quality evaluation.
- Reports image reconstruction and semantic recovery metrics such as PSNR, SSIM, and NC.

## Repository Layout

```text
.
|-- Pluto_test.m             # Main Pluto/HybridBSC demo
|-- pluto_test_mnist.m       # MNIST JPEG transmission demo
|-- pluto_test_ori.m         # Original image array transmission demo
|-- mnist_func.py            # Python functions called from MATLAB
|-- mnist_test.py            # PyTorch encoder/decoder training and testing
|-- AddWatermark.m           # Semantic insertion core
|-- PickWatermark.m          # Semantic extraction core
|-- JPEGEncode.m             # JPEG coding utilities
|-- bpg_enc.m / bpg_dec.m    # MATLAB wrappers for BPG tools
|-- bpg/                     # Third-party BPG command-line binaries and docs
|-- data/                    # MNIST sample data
|-- *.mat, *.npy, *.pth      # Demo data, models, and experimental assets
```

## Requirements

MATLAB:

- MATLAB R2021a or later is recommended.
- WLAN Toolbox
- Communications Toolbox
- DSP System Toolbox
- Image Processing Toolbox
- ADALM-Pluto Radio Support Package, only for over-the-air experiments

Python:

- Python 3.9 or later
- PyTorch
- TorchVision
- NumPy
- Matplotlib
- scikit-image
- imageio

Install the Python dependencies with:

```bash
pip install -r requirements.txt
```

Then check the MATLAB Python binding:

```matlab
pyenv
py.importlib.import_module("torch");
py.importlib.import_module("numpy");
py.importlib.import_module("skimage");
py.importlib.import_module("imageio");
```

## Quick Start

Open MATLAB and enter the project directory:

```matlab
cd("path/to/HybridBSC")
```

Run one of the entry scripts:

```matlab
Pluto_test
pluto_test_mnist
pluto_test_ori
```

For simulation-only experiments, set the channel mode inside the script to:

```matlab
channel = "GaussianNoise";
```

For ADALM-Pluto over-the-air experiments, set:

```matlab
channel = "OverTheAir";
```

and confirm that the Pluto device is connected and visible to MATLAB.

## Main Parameters

`pluto_model` controls the modulation mode:

- `1`: QPSK
- `2`: 16QAM
- other values: 64QAM

`pluto_channel_model` controls the simulation channel:

- `1`: AWGN
- `2`: Rayleigh fading + AWGN
- other values: Rician fading + AWGN

## Data And Model Files

The GitHub repository is intentionally kept lightweight. Large generated assets are not committed to the main branch:

- MNIST arrays: `x_train.npy`, `x_test.npy`, `mnist.npz`
- MATLAB result files: `*.mat`
- BPG Windows binaries: `bpg/*.exe`, `bpg/*.dll`
- Generated receive-side images and compressed files

Generate the MNIST NumPy arrays before running MATLAB scripts that call `mnist_func.py`:

```bash
python prepare_demo_data.py
```

The script uses local `mnist.npz` if present. If `mnist.npz` is absent, it downloads MNIST through TorchVision and writes `x_train.npy` and `x_test.npy`.

For BPG experiments, install BPG separately or copy compatible `bpgenc`/`bpgdec` binaries into `bpg/`.

Some generated receive-side files, local experiment outputs, and duplicate MNIST raw caches are ignored by `.gitignore` to keep future commits manageable.

## Asset Policy

For a paper-demo repository, it is better to keep the main branch readable and small. Large assets can be attached later as GitHub Release files, linked from Zenodo/figshare/Google Drive, or regenerated by scripts.

If a script reports a missing generated file, rerun the corresponding upstream demo step or regenerate the MNIST data with `mnist_test.py` / `mnist_func.py`.

## Typical Outputs

Depending on the selected experiment, the scripts may generate:

- `tx_img.jpg`, `tx_img.bpg`
- `rx_img.bpg`, `rx_img.png`
- `data_1.txt`, `data_2.txt`
- `com_tx.jpg`, `com_rx.jpg`
- PSNR, SSIM, and NC result matrices

These files are treated as experiment outputs and should generally not be committed unless they are intentional examples.
